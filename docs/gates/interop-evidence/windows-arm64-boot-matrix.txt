## Root cause analysis

### The 0x10000000 conflict (nix firmware only)

The nix EDK2 firmware (hash 47765fe3) exhibits:
  ConvertPages: failed to find range 10000000 - 1012BFFF

This range is exactly 0x12C000 bytes = 640 × 480 × 4 bytes.
QemuRamfbDxe defines a 640×480 32-bpp mode.
The error is non-fatal WITHOUT a display device, but when ramfb or
virtio-gpu-pci is added, bootaa64.efi's StartImage() times out.

### UTM firmware (hash ee769c4b) does NOT exhibit this conflict

When the UTM firmware is used with the SAME nix QEMU 10.2.4 binary:
- NO ConvertPages error appears in serial log
- bootaa64.efi loads and starts successfully
- ramfb and virtio-gpu-pci both initialize correctly
- Windows PE ARM64 boots and shows the Setup GUI

This proves the issue is the EDK2 FIRMWARE BUILD, not the QEMU version
or the display device. The nix firmware's memory map conflicts with
ramfb's 640×480 framebuffer allocation; UTM's firmware does not.

### Working configuration (nix QEMU + UTM firmware)

qemu-system-aarch64 \
  -L <UTM_CACHE> \
  -nodefaults \
  -cpu host -smp cpus=4,sockets=1,cores=4,threads=1 \
  -machine virt -accel hvf \
  -drive if=pflash,format=raw,unit=0,file=<UTM_CODE.fd>,readonly=on \
  -drive if=pflash,unit=1,file=<UTM_VARS_padded.fd> \
  -m 4096 \
  -device nec-usb-xhci,id=usb-bus \
  -device usb-tablet,bus=usb-bus.0 \
  -device usb-kbd,bus=usb-bus.0 \
  -device virtio-blk-pci,drive=maindisk \

  -device usb-storage,drive=autounattend_fat,removable=false,bus=usb-bus.0 \

Result: Windows PE ARM64 boots, virtio-gpu provides 800×600 display,
Windows Setup GUI is visible (language selection screen confirmed
via pixel analysis: 16.8% non-black, text at Y=65-133 and Y=172-427,
Next button at Y=559-570).

### Remaining issue

Windows Setup shows the language selection screen instead of
auto-processing the Autounattend.xml. WinPE searches for
autounattend.xml on removable media; the FAT image approach places
it correctly but WinPE may need specific enumeration order or the
Autounattend.xml schema may need adjustment for ARM64 WinPE.

The VM runs at ~100% CPU for extended periods (Windows installer
active) but the qcow2 disk file doesn't grow visibly (qcow2 write
caching). The installation has not yet completed.
